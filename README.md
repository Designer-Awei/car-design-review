# 汽车设计评价

从用户指定的车型出发，按“视觉素材与初评 → 设计背景与品牌故事 → 主题提炼 → 叙事初稿 → 审核”的顺序，逐步生产完整的汽车设计科普文档。支持飞书、Word 与 PDF；默认聚焦外观。

本仓库沉淀自 GT-R R35 参考文档，以及 2026款福特野马（Mustang）、2024款雪佛兰科迈罗（Camaro）的实际协作。2026-10-30，用户认可交付成果，并要求把方法、原始参考和迭代经验一起保留下来。

## 这次协作形成的方法

1. **先找得到、看得清，再谈得有依据。** 素材需要覆盖多视角，确认年款、版本与来源；每张图立即写 PFDBI 初评，先完成一份可以阅读的视觉素材章节。
2. **主题决定叙事的方向。** “比例、形体、细节都不错”只是一组判断。“流线让力量舒展”“把力量压成工业雕塑”，才能把这些判断组织成一篇有作者立场的文章。主题要从图像与研究中生长出来。
3. **用形式解释感觉。** 长机盖为什么有力量？要写清它与车轮、前悬、后移座舱的关系。专业性来自可见的证据与解释，而不靠堆术语。
4. **研究可以细，正文要顺。** 让历史、设计潮流、工程与人的欲望形成故事。把资料核验放在研究层；正文不反复插入“不能据此认定”等防御性限定。
5. **主角始终是指定车型。** 老款比较、媒体观点和宏观历史用来解释它，选关键变化即可。外观是主体，内饰按用户需要增加。
6. **做一部分，就写一部分。** 飞书分段保存并回读；本地文档分阶段保存版本。最终检查主题是否贯穿、想表达的观点是否落入初稿，而不只是检查字数。
7. **把下一次做好的理由也留下来。** 每次调用记录真实反馈、修改与验证结果；经验证的方法再进入稳定原则，避免把一辆车的特征变成所有车型的套路。

## 使用

Skill 位于 [skills/car-design-review/SKILL.md](skills/car-design-review/SKILL.md)。可直接让代理读取这个文件；需要自动发现时，把整个 `car-design-review` 文件夹安装到运行环境支持的 skills 目录。原始参考和 evolution 必须随 skill 一起保留。

示例请求：

> 使用 $car-design-review，为 2026款福特野马（Mustang）制作汽车外观设计评价文档，输出到我给出的飞书链接。工作目录为我指定的项目路径。每车初稿约1500字，按阶段写入，围绕一个有辨识度的主观主题展开。

> 读取本仓库的 skill，研究我指定的车型，交付包含多视角图片、初评、品牌故事、媒体观点、主题和完整初稿的 Word 与 PDF。先核对具体年款及版本，在我的项目目录里保存所有资料。

只有车型名称也可以启动：代理会核对当前车型、年款、市场与版本，提出并采用有依据的主题。缺少本地工作目录时先确认目录，再保存产物。历史车型保留指定年款，不替换成新款。

## 仓库内容

- `skills/car-design-review/SKILL.md`：执行入口与分阶段 SOP。
- `references/originals/`（位于 skill 内）：PFDBI 原始 PDF、可检索文本，以及 ToTo文翰三篇完整原文附件。
- `references/`：结构规范、研究方法、文案方法、交付方式、质量审核，以及成果示例。
- `assets/templates/`：文档骨架、图片/来源台账、主题卡、观点覆盖清单、迭代记录模板。
- `evolution/`：本次协作复盘、稳定原则与后续调用记录。
- `scripts/`：参考完整性核验、记录一次调用的辅助工具。

以上相对路径除首项外，均相对于 `skills/car-design-review/`。所有引用使用相对路径，不依赖本次电脑的盘符或飞书登录状态。

## 参考与分享

[原始参考索引](skills/car-design-review/references/originals/README.md)记录来源、原文件名、快照版本及 SHA-256。三篇 ToTo文翰文章保留原文与署名，供学习叙事方法；PFDBI 是用户提供的方法原件。原参考材料的作者和来源归属保持不变。

仓库未包含飞书登录凭证、用户令牌、CLI 日志或车型图片包；运行缓存与各次项目产物默认忽略。远程仓库为 [Designer-Awei/car-design-review](https://github.com/Designer-Awei/car-design-review)，创建时设为私有。

`.gitattributes` 保留原始TXT附件的换行与字节内容，同时统一方法文档和脚本的换行，方便跨平台协作与哈希校验，建议保留。`.cache/` 只是本地工作缓存，不是skill必需文件，也不进入版本库；没有程序使用时可清理。

## 核验与迭代

在仓库根目录执行（Python 3.10+，标准库）：

```sh
python skills/car-design-review/scripts/validate_package.py skills/car-design-review
```

每次使用结束，填写 `assets/templates/evolution-run.json` 的副本，然后执行：

```sh
python skills/car-design-review/scripts/record_run.py --input <本次记录.json>
```

工具只新增本地复盘文件，并更新 `evolution/index.json`；不改写用户文档，不自动改变稳定规则，不推送远程。Skill 会在下一次调用时读取稳定原则和相关记录，把已经验证有效的经验用于新任务。
