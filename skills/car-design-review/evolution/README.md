# 每次调用后的持续迭代

## 什么时候读

开始任务先读 `principles.md` 与 `index.json`，再读与车型研究、文案风格或交付工具有关的最近记录。长日志不全部装入上下文。原始参考保持稳定，不能用越来越长的复盘取代阅读原文。

## 每次必须记录什么

- 本次任务、车型、范围、输出格式与结果。
- 用户真实反馈；没有就记“未收到”，区分明确评价与作者推测。
- 具体问题、采用的修改、验证证据与未完成限制。
- 可复用技巧、适用范围、候选改进和已获验证的稳定原则。

文件建议 `runs/YYYY-MM-DD-简短任务标识.md`。不要保留完整聊天、认证信息、隐私资料或无必要的运行日志。关键原话可短引，配合上下文说明。

## 操作

从 `../assets/templates/evolution-run.json` 复制本次输入，在项目工作目录填写真实内容；用 skill 的 `scripts/record_run.py --input <文件>` 新增记录并更新索引。模板和脚本使用相对路径，对安装盘符没有要求。重复 run_id 会被拒绝，避免覆盖旧经验。

脚本不自动改变 `SKILL.md` 或稳定规则。完成记录后由代理判断：

- 用户明确要求且已验证有效的习惯，可进入 `principles.md`，注明来源记录与适用范围；同步修改真正受影响的方法文件，避免多个地方规则冲突。
- 只在一台车有效的主题、比例或审美，不提升为所有车型的规定。
- 尚未尝试的建议标为候选；失败和阻碍如实保留。
- 用户后续纠正时新增证据，修改当前稳定原则；历史记录保留，不抹掉发生过的修订。

目录只读或没有更新 skill 的权限时，在本次项目目录保存待合并记录，并说明尚未并入 skill；继续完成原任务。不要为写经验阻断交付，也不擅自改写其他 skill、全局配置或远端仓库。
