# 飞书、Word与PDF的交付适配

先建立同一份内容与图片/来源台账，再按用户选择呈现。兼容指标题、图片、初评、研究、主题与完整文案都能保留；不要求三个工具使用完全相同的底层块结构。

## 共同约定

- 项目目录保存 `assets/`、`sources/`、`drafts/`、`qa/`、`outputs/` 和 `.cache/`；不把运行产物写回 skill 的原始参考目录。
- 保存可编辑主稿，记录图号、实际文件路径、图注、来源与章节归属。Word/PDF不要依赖远程图片加载。
- 文档名与正文标题分别处理。标题等级以参考为准，不能用加粗大字伪装 Heading。
- 专业术语、中文（English）车型名与图号跨格式一致。采用同一内容版本导出，禁止飞书改完而PDF沿用旧稿。
- 故事/初稿是独立的编辑单元，有主题标题，正常换段，不把全文做成一张图片。

## 飞书

1. 优先用可用的飞书连接器或 CLI。若环境提供 `lark-doc`、`lark-drive` 等 skill，先按对应场景读取；没有则使用当前工具实际支持的操作，不凭本文件猜接口。
2. Wiki URL 先由工具解析为真实文档；读取参考、目标的最新标题结构。编辑时获取完整块ID，保留用户新增内容、批注与资源。
3. 每阶段局部插入或替换相应章节。写前确认最新块ID与相关内容，写后回读；不要用旧快照整篇覆盖。
4. 本项目验证过的 CLI 形式如下，仅在当前 `--help` 和 skill 文档仍支持时使用：

```sh
lark-cli docs +fetch --doc <目标URL> --detail full --as user
lark-cli docs +update --doc <目标URL> --command block_replace --block-id <真实块ID> --content @./drafts/section.xml --as user
```

XML 内使用原生 `<h1>`、`<h2>`；本地图片通过工具的正式上传路径嵌入。独立初稿可使用带 caption 的 `<pre lang="Plain Text" wrap="true"><code>...</code></pre>`，段落用 `<br/>`；当前平台支持更合适的可编辑文本容器时也可采用。正文按工具要求转义，图文不得因转义损坏。

5. 某些读取结果的 `ol` 只是无ID的合成包装；操作真实子块。避免全局替换简称，曾导致“中文名（English）”重复嵌套。精确编辑内容块；caption可能需要单独更新。
6. “写入成功”须有工具成功返回和远端回读。核对图片数量、图注、标题层级与文本块；查看实际图片预览。新增图片逐一检查，修改已有内容则确保原图片未丢失。
7. CLI 缺失能力或授权失败时，记录准确限制，继续完成不依赖它的研究和本地主稿。需要浏览器时先读当前电脑操作规范。既有授权下推进，不能把没有发生的远端写入当完成。

## Word / DOCX

使用当前环境的文档生成能力；提供 Documents skill 时按其生成与渲染流程执行。保留原生 Title、Heading 1/2、段落、图注和超链接，输出可编辑 `.docx`。没有特定引擎时可采用支持中文、图片嵌入和样式的 Word 库，不手工拼装不完整的XML包。

- 默认 A4，中文可读正文字号，使用本机确实存在的中文字体；标题层级和段前段后一致。用户有模板时优先模板。
- 图片按页面可用宽度等比缩放，不变形。图注、来源和初评紧跟图，控制孤行和空白。
- “独立文本块”用主题标题加正文段落，可加浅底/边框；长文允许分页，保持编辑和自动换行。不要把1500字塞进固定高度文本框，也不要强制代码字体。
- 链接显示可读标题；来源较多时放文后书目，与图号/引用对应。
- 保存阶段版本；最终渲染并检查各页，尤其图片密集页、文本块跨页、来源页与中文换行。报告未能渲染的限制，不以“文件能打开”冒充版式核验。

## PDF

需要 Word/PDF 两种时，先完成同一个可编辑主稿，再通过可用办公渲染器导出PDF，以减少版本差异。只需要PDF时可用当前 PDF 工具从结构化主稿直接排版。

嵌入/正确替代中文字体，保证文本可检索、图片清晰、图注与超链接可用。生成后渲染查看最终页面，检查裁切、重叠、缺字、孤立标题、图片遗漏和页码。遇到问题回到主稿修正再导出，不在未修正的旧版本上继续验收。

## 交付说明

给用户可打开的飞书链接或实际文件。简洁说明阶段/成果、核验情况与仍存在的具体限制。输出路径遵循用户当前任务指定目录；平台固定位置的例外按当前规则说明和迁移。没有请求发布、推送或对外分享时，不附加这些动作。
