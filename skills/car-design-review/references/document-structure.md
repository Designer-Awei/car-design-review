# 默认文档结构与层级

来源：用户的 GT-R R35 设计评价，结构快照见 [r35-outline.json](examples/r35-outline.json)。这是一份研究材料与文案合一的工作文档。最终文章只是其中“初稿文案”的部分。

## 单车结构

文档名称使用原生 Title，**正文的一级标题使用 Heading 1 / `<h1>`**。顺序固定如下：

1. h1 设计背景
2. h1 参考链接
3. h1 视觉素材（实际年款）
   - h2 主体比例
   - h2 局部细节
   - h2 车漆配色
4. h1 品牌故事
   - h2 关键代际/改款节点：变化的设计含义
   - 视内容设置2–4个节点，避免机械复制 R35 的07/17/25年份。
5. h1 外部视角
6. h1 结构化提示词
7. h1 初稿文案

“结构化提示词”放 PFDBI 方法附件/引用、采用的主题、观点、视觉锚点、叙事顺序、篇幅与风格要求，便于下次继续加工。“初稿文案”放一个有主题标题的完整可编辑文本块，内部可有少量叙事小节；这些小节不新增与研究章节竞争的一级目录。

## 多车结构

每辆车分别重复上述完整序列，使用分隔线或用户已有的车型组标题区分。用户已有 h1 车型标题与 h1 研究章节并列时，保留；不能为了“美化”擅自把研究章节改成 h2。若用户要重新规划多车层级，可统一为车型 h1/章节 h2/素材类别 h3，但这属于另一个明确选择，不能一边声称严格复刻、一边更换层级。

## 每张图片组成

图片 → 图号及图注 → 可点击来源 → 初评。也可依参考的图文顺序排布，但这四项不能缺。

图注应能识别“年份、车型、版本、视角”。初评围绕这张图片能展示的内容，避免每张都重复长车头、低车顶等整车总结。同一张图可链接多个 PFDBI 维度，不在阅读层堆缩写。

“主体比例”优先完整外观视角；“局部细节”用真实近景；“车漆配色”解释颜色、反射、明暗如何塑造性格，而不只罗列色号。历史图少量加入品牌故事，当前车型的主素材保持纯粹。

## 可选历史专题

多车之后独立增加 h1，例如“美式肌肉车是怎么演进出来的”。顺序：主题句 → 约1000字独立叙事文本块 → 可靠来源 → h2 研究分节。

研究分节可以按时期梳理；**故事正文要有欲望、问题、变化和因果的推进**。两个层次各司其职，既方便科普发布，也保留研究深度。

## 篇幅建议

每车约1500字初稿，历史故事约1000字；按用户实际要求调整。正文主体留给指定车型，旧款的关键比较常用1–3处即可，不设硬比例。初评与研究不计入初稿字数；历史专题也单独计算。
